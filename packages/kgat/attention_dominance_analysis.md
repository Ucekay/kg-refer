# KGATにおけるアテンションスコアの支配性が埋め込み伝播に与える影響の考察

## 問題の概要

KGATの学習において、一部のtailノード（特に地理的エンティティやカテゴリエンティティ）のアテンションスコアが支配的（0.9以上）になり、他のtailノードのスコアが非常に小さくなる（0.001以下）現象が観察される。

## 埋め込み伝播のメカニズム

### 1. 伝播式

```python
# aggregator.py の forward メソッド
side_embeddings = torch.matmul(A_in, ego_embeddings)
```

各レイヤーで、A_inマトリックスと現在の埋め込みの行列積を計算する。

### 2. A_inの性質

- A_inは`dim=1`（各headノードから出るエッジ）に対してsoftmax正規化されている
- 同じheadノードから出るすべてのエッジのスコアの合計は1
- 1つのエッジが支配的（例：0.98）だと、他のエッジは合計で0.02程度になる

### 3. 実際の伝播

アイテム10476の例：
- "Reno" (located in): 0.9888
- 他の52個のエッジ: 合計0.0112

伝播時の計算：
```
side_embedding[item_10476] = 0.9888 * embedding[Reno] + 0.0024 * embedding[User_4440] + ...
                           ≈ 0.9888 * embedding[Reno]  (他の項は無視できるほど小さい)
```

## 問題点の考察

### 1. **情報の多様性の喪失**

**問題：**
- 支配的なtailノード（例：地理的エンティティ）の埋め込みがほぼそのまま伝播される
- 他のtailノード（ユーザーインタラクション、特徴、属性など）の情報がほとんど反映されない

**影響：**
- 埋め込みが地理的エンティティやカテゴリエンティティに過度に依存する
- 細かい特徴やユーザーインタラクションパターンが埋め込みに反映されにくい
- 類似アイテムの識別が地理やカテゴリに偏る可能性

### 2. **学習の非効率性**

**問題：**
- 多くのエッジ（例：52個中51個）が実質的に無視される
- これらのエッジの埋め込み更新への寄与が極めて小さい

**影響：**
- 知識グラフの豊富な情報が活用されない
- 学習データの大部分が無駄になる可能性
- モデルの表現力が制限される

### 3. **過学習のリスク**

**問題：**
- 特定のタイプのエンティティ（地理、カテゴリ）に過度に依存
- 他の情報源からの正則化効果が弱い

**影響：**
- テストデータで地理やカテゴリが異なる場合の汎化性能が低下する可能性
- 多様な特徴を持つアイテムの表現が不十分になる可能性

### 4. **階層的構造の偏重**

**問題：**
- 階層的な関係（"is a", "located in"）が支配的
- より細かい関係（"serves", "has feature", "InteractedBy"）が軽視される

**影響：**
- アイテムの詳細な特徴が埋め込みに反映されにくい
- 推薦の説明可能性が低下する可能性（なぜこのアイテムが推薦されたかが地理やカテゴリに偏る）

## 利点の考察

### 1. **重要な情報の強調**

**利点：**
- 地理やカテゴリは確かに重要な情報
- モデルが重要な情報を自動的に識別している

### 2. **計算効率**

**利点：**
- 実質的に1つの主要なエッジのみを考慮すればよいため、計算が効率的
- ただし、これは情報の多様性の喪失とトレードオフ

## 改善案

### 1. **温度パラメータ付きsoftmax**

```python
# より緩やかな分布にする
A_in = torch.sparse.softmax(A_in / temperature, dim=1)
```

温度パラメータを大きくすると、分布がより均一になり、多様な情報が伝播される。

### 2. **アテンションスコアの上限設定**

```python
# 最大アテンションスコアに上限を設ける
max_attention = 0.5  # 例：最大50%
```

1つのエッジが支配的になることを防ぐ。

### 3. **関係タイプごとの重み付け**

```python
# 関係タイプごとに異なる重みを適用
relation_weights = {
    "located in": 0.3,
    "is a": 0.3,
    "InteractedBy": 0.2,
    "serves": 0.1,
    # ...
}
```

地理やカテゴリ以外の情報も適切に反映されるようにする。

### 4. **マルチヘッドアテンション**

複数のアテンションヘッドを使用し、異なる関係タイプに焦点を当てる。

### 5. **レイヤーごとの異なるアテンション**

浅いレイヤーでは多様な情報を、深いレイヤーでは重要な情報を強調する。

## 結論

**問題の程度：中程度〜高**

一部のtailノードのアテンションスコアが支配的になることは、以下の理由で問題となる：

1. **情報の多様性の喪失**：知識グラフの豊富な情報が活用されない
2. **学習の非効率性**：多くのエッジが実質的に無視される
3. **汎化性能への懸念**：特定の情報源に過度に依存するリスク

ただし、地理やカテゴリが重要であることは確かであり、完全に均一な分布を目指す必要はない。

**推奨される対策：**
- 温度パラメータ付きsoftmaxの導入
- アテンションスコアの上限設定
- 関係タイプごとの重み付け

これにより、重要な情報を保持しつつ、多様な情報も適切に反映されるバランスの取れた埋め込み伝播が可能になる。
